# Product

## Register

product

## Users

Software engineering teams — developers, designers, and leads — managing collaborative work. Primary user is a developer or project lead who opens the board multiple times per day to check task status, move work forward, or quickly create tasks during a standup or code review.

## Product Purpose

Taskatra is a self-hosted collaborative task management tool built for engineering teams who want Linear-quality ergonomics without third-party SaaS. Teams create projects, invite members, manage tasks on a Kanban board, and see changes as they happen. Success: a team can open a project board and know exactly what state every task is in, who owns it, and what's blocking without scrolling, drilling down, or leaving the board.

## Brand Personality

Precise, direct, fast. The brand says: "we built this right." Not startup-flashy, not enterprise-heavy. The kind of tool a good engineer would build for themselves.

## Anti-references

- Generic SaaS violet/indigo-everything (the Tailwind default trap)
- Overwrought dashboard chrome with sidebars, topbars, breadcrumbs, and status bars all competing
- Big gradient hero cards, glass effects, or anything that reads as "AI-generated UI template"
- Notion's soft beige editorial feel — Taskatra is a task tool, not a document editor

## Design Principles

1. **Amber is the signal.** One accent color, used sparingly for action and active state. Amber-500 only on things that demand attention or invite action.
2. **Task first.** The title is the most important thing in any task interface. All other metadata is secondary and should feel secondary — compact, subordinate, never competing with the work itself.
3. **Earn every pixel.** No decorative chrome. Every visible element earns its place by communicating state or enabling action.
4. **Zinc neutrals carry the surface.** Background, borders, text hierarchy — all zinc. Amber is contrast, not background.
5. **Consistent with itself.** The app interior and the marketing page share the same brand. A user who sees the landing page should recognize the app immediately.

## Accessibility & Inclusion

WCAG AA minimum. Dark and light mode required (system preference respected, manual toggle available). All interactive elements keyboard accessible. Color not the sole indicator of state — use labels alongside color badges.
